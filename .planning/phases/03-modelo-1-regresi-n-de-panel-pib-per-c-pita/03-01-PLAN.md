    — returns `{"statistic": float, "df": int, "pvalue": float}` via the
    exact formula verified in 03-RESEARCH.md Finding 2:
    `H = (b_FE - b_RE)' [Var(b_FE) - Var(b_RE)]^-1 (b_FE - b_RE) ~ chi2(k)`,

    excludes RE's intercept). Falls back to `numpy.linalg.pinv` (with a

    pathology (03-RESEARCH.md Finding 2), not a bug to hide.

    — returns `{"statistic": float, "pvalue": float}` via the exact
    formula verified in 03-RESEARCH.md Finding 2:
    `CD = sqrt(2/(N(N-1))) * sum_{i<j} sqrt(T_ij) * rho_hat_ij ~ N(0,1)`.
    `residuals` is expected to carry a `(entity, time)` MultiIndex (e.g.
    `fe_results.resids`, directly usable without transformation). Handles
    unbalanced panels natively via per-pair `.dropna()` (verified live —
    03-RESEARCH.md's synthetic test used exactly this approach).
  - `choose_cov_type(pesaran_result: dict[str, float], alpha: float = 0.05) -> tuple[str, dict[str, Any]]`
    — returns `("kernel", {"kernel": "bartlett"})` if
    `pesaran_result["pvalue"] < alpha` (reject H0 of no cross-sectional
    dependence → Driscoll-Kraay), else `("clustered", {"cluster_entity": True})`.
    The returned tuple's second element is the exact `**cov_config` to
    splat into `fit_panel_model(..., cov_type=result[0], **result[1])`.

### Issues found and fixed

**1. [FIXED — test-design flakiness risk] The original draft asserted
`entity_effects=False` would produce a "larger-magnitude, less precise"
coefficient than the two-way-effects fit.** This synthetic panel is
deliberately constructed with an entity effect UNCORRELATED with the
regressor (needed so the Hausman/Pesaran tests in Task 2 have a clean,
known-consistent null case — both FE and RE should be consistent estimators
on this data, which is exactly what makes it a good test fixture for "fails
to reject H0"). But that same property means dropping `entity_effects`
would NOT reliably shift the coefficient's magnitude in a predictable
direction — there's no omitted-variable-bias mechanism at play by
construction. Asserting a specific direction on this data would be a flaky
test tied to the random seed's specific draw. **Fix applied:** the test now
asserts only that `rsquared` (or `std_errors`) measurably DIFFERS between
the two fits — proving the effects flags are not silently ignored — without
claiming a direction that isn't actually guaranteed by this fixture's
design.

**2. [FIXED — needed concrete numbers] The hand-computable Pesaran CD test
was originally specified only qualitatively** ("3 entities × 3 periods with
a manually-computable pairwise correlation") without exact values, leaving
the executor to derive both the fixture AND the expected statistic from
scratch — workable, but less rigorous than the deep_work_rules convention
of giving concrete values directly. **Fix applied:** embedded an exact,
independently-verified fixture (entities A=[1,2,3], B=[1,2,3] (ρ=1 with A),
C=[3,2,1] (ρ=-1 with A)) with its exact expected result
(`CD = -1.0`, verified via direct Python computation during this review, not
just algebra) directly in the task's `<action>`.
