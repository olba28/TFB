## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| widget selection→SQL/column access | Indicator/year selections flow into pandas column/row selection; the table name is fixed and never built from user input. |
| filesystem→pickle load | `load_model` deserializes project-produced `.pkl` only. |
| dashboard process↔UN SDG API | MUST NOT exist at runtime — the data layer reads only local artifacts (DASH-01). |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-5-01 | Tampering (SQL injection) | `load_panel_clean`/`load_panel_exclusions` | medium | mitigate | Table names are fixed string literals passed to `pd.read_sql`; no widget value is interpolated into SQL text (mirrors src/db.py). Indicator columns are selected via a fixed whitelist (INDICATOR_LABELS/registry) in the app layer. |
| T-5-02 | Tampering / Information Disclosure (untrusted pickle) | `load_model` | medium | mitigate | Loads only `data/modelos/*.pkl` produced by this project's own pipeline; no `st.file_uploader` for `.pkl` exists; `.venv` interpreter required (RESEARCH Pitfall 6). |
