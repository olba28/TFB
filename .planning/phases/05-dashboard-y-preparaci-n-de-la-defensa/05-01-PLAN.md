## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| filesystem→dashboard process | The dashboard loads `.pkl` model artifacts and reads `panel.db` from the local filesystem; these must be project-produced, never user-uploaded or network-fetched. |
| (no network boundary) | This plan creates config/registry/fixtures only — no runtime network surface. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-5-02 | Tampering / Information Disclosure | `models.ACTIVE_MODELS` pkl_path values (pickle sources) | medium | mitigate | Registry paths point only to project-produced `data/modelos/*.pkl`; no `st.file_uploader` for `.pkl` is introduced anywhere in the phase (RESEARCH Security Domain). |
| T-5-03 | Elevation of Privilege (network exposure) | `.streamlit/config.toml` | low | mitigate | Config sets `[theme]` only; no `[server]`/`server.address` key added — Streamlit stays on its localhost default binding (PROJECT.md: local-only). |
| T-5-SC | Supply Chain / Tampering | package installs | low | accept | No new package is installed in this plan (streamlit/plotly/sqlalchemy already pinned); `kaleido` is deliberately NOT installed this phase (RESEARCH Open Question 1). |
