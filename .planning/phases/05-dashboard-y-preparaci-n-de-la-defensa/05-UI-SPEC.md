# Phase 5 — UI Design Contract

> Visual and interaction contract for the Streamlit + Plotly local dashboard (Phase 5: Dashboard y Preparación de la Defensa). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Context note:** This is a solo academic thesis project. There is no existing frontend, brand, or component library anywhere in the repo — Phases 1–4 were pure data/econometrics/notebooks. This dashboard is the project's first and only UI surface, built for a single live oral-defense demo (not a commercial product). The contract below is scoped to be legible, consistent, and professional for an academic tribunal — proportionate to that reality, not a heavyweight design system.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — pure Python/Streamlit project, no npm/React toolchain, shadcn not applicable (confirmed: no `components.json`, `package.json`, or `tailwind.config.*` in repo) |
| Component library | Streamlit native widgets only (`st.tabs`, `st.columns`, `st.selectbox`, `st.dataframe`, `st.metric`, `st.container`) + Plotly Express for charts. No custom React/HTML components. |
| Icon library | none — do not use emoji or icon shorthand in tab labels or headers (keeps a formal academic tone; also avoids the D-06-locked tab labels drifting from their exact text) |
| Font | Streamlit's default theme font (Source Sans / system sans-serif fallback). No custom `@font-face` or font injection — avoids a fragile CSS override breaking mid-demo. |

**Theme mechanism:** Declare the palette below via `.streamlit/config.toml` `[theme]` block (Streamlit's supported, stable theming mechanism) rather than injected CSS/`st.markdown(unsafe_allow_html=True)`. This keeps the whole visual contract in one config file, editable without touching `app.py`, and safe against Streamlit version upgrades.

## Component Inventory

Prescriptive list of the Streamlit/Plotly primitives this phase uses — executor should not introduce alternatives (e.g. no `st.plotly_chart` replaced by raw HTML iframes, no custom CSS grid replacing `st.columns`).

| Component | Usage |
|-----------|-------|
| `st.set_page_config(layout="wide")` | Called once at the top of `app.py` — wide layout needed for side-by-side choropleths (D-02) |
| `st.title` | App-level display heading (once, top of `app.py`) |
| `st.caption` | Subtitle under the title; per-map "no data" explanatory notes; cold-start timing readout (sidebar) |
| `st.tabs([...])` | Top-level navigation — exact 4 labels locked by D-06, see Copywriting Contract |
| `st.columns(2, gap="large")` | Side-by-side comparison in "Mapa e indicadores" (D-02) — `gap="large"` visually separates the two independent choropleths |
| `st.selectbox(..., key=...)` | Indicator/model pickers — **always** pass an explicit unique `key=` (Pitfall 3, RESEARCH.md: avoids `DuplicateWidgetID` when two selectboxes share a label pattern) |
| `st.plotly_chart(fig, use_container_width=True)` | All Plotly figures (choropleth, scenario plot, PDP) — always `use_container_width=True` so figures fill their column at any window size during the demo |
| `st.dataframe` | Model 1 coefficient/diagnostic tables |
| `st.metric` | Headline numbers (e.g. simulated GDP delta per scenario) — use `st.metric`'s built-in label/value/delta layout rather than hand-formatted `st.write` strings |
| `st.container(border=True)` | Groups a chart + its caption/legend as one visual block per tab section |
| `st.error` | Missing/corrupt artifact fallback (see Copywriting Contract → Error state) |
| `st.sidebar` | Reserved only for the cold-start timing readout (RESEARCH.md code example) — no navigation lives in the sidebar; navigation is tabs only (D-06) |
| `shap.summary_plot` via `st.pyplot` | SHAP tab only — uses SHAP's own default matplotlib diverging red/blue palette, not restyled (see Color section) |

## Spacing Scale

Declared values (must be multiples of 4). Streamlit manages most container spacing itself; this scale governs the few places this phase has direct control (Plotly figure margins, `st.columns` gap choice, spacing between stacked elements within a tab).

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Plotly figure margin `l`/`r` (choropleths sit flush against their column edges) |
| sm | 8px | Plotly figure margin `b`; gap between a `st.metric` label and its value; `st.columns(gap="small")` equivalent (not used in this phase — see xl) |
| md | 16px | Default vertical gap between stacked elements within a tab (blank `st.write("")` / natural Streamlit block spacing); Plotly figure margin default padding around legend |
| lg | 24px | Padding above each `st.subheader` section break inside a tab; Plotly figure margin `t` for standalone charts with no title (title clearance) |
| xl | 32px | Plotly figure margin `t` when the figure has its own title; conceptually maps to `st.columns(2, gap="large")` in the comparison tab (D-02) |
| 2xl | 48px | Space between `st.title` and the first tab's content (`st.caption` + `st.tabs` block) |
| 3xl | 64px | Not used — this is a single-page tabbed app with no page-level sections beyond the 4 tabs (D-06); no element requires this much isolation |

Exceptions: Plotly's `animation_frame` slider/play controls (D-05) are rendered natively by Plotly and are **not** subject to this spacing scale — they are excluded from restyling per D-05's explicit choice of the native mechanism.

## Typography

Streamlit itself renders most typography via its own theme (headers, widget labels, body text) — this phase does not override Streamlit's internal CSS. The table below is the contract for (a) which Streamlit heading element to use for each role, and (b) explicit font sizes for Plotly figure titles/axes/legends, which this phase's code does control directly (`plots.py`).

| Role | Size | Weight | Line Height | Streamlit / Plotly mapping |
|------|------|--------|-------------|------------------------------|
| Body | 16px | 400 (regular) | 1.5 | Streamlit default body text (`st.write`, `st.dataframe` cell text, `st.caption` uses a smaller variant — see Label) |
| Label | 14px | 400 (regular) | 1.5 | `st.caption`, widget labels (`st.selectbox` label text), Plotly axis tick labels/hover text |
| Heading | 20px | 600 (semibold) | 1.2 | `st.subheader` (section headings within a tab); Plotly figure `title.font.size` |
| Display | 28px | 600 (semibold) | 1.2 | `st.title` (app-level heading, once) |

Font weights used: **exactly 2** — 400 (regular body/label) and 600 (semibold heading/display). Do not introduce bold (700) or light (300) variants.

Tab labels (`st.tabs`) and `st.metric` labels/values use Streamlit's own fixed internal sizing (not independently overridable) — excluded from this table by design, not an oversight.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` | Main app background (Streamlit `backgroundColor`) |
| Secondary (30%) | `#EFF3F7` | Sidebar background, `st.container(border=True)` fill, `st.metric` card background (Streamlit `secondaryBackgroundColor`) |
| Accent (10%) | `#1B6CA8` | Reserved for: Streamlit `primaryColor` (selectbox/slider focus ring, any button), the fitted-value/reference line in the Modelo 1 tab's diagnostic chart, the headline number in `st.metric` for the simulation's central estimate |
| Destructive | not applicable | This dashboard has no destructive actions (read-only exploration of pre-computed artifacts, no delete/overwrite/reset widgets) — no destructive color declared |

Accent reserved for: primary widget focus states (Streamlit-applied automatically via `primaryColor`), the fitted/reference line drawn on top of the Modelo 1 diagnostic chart, and the central-estimate number in each simulation `st.metric`. **Never** used as the choropleth data-color scale (see below) — those are separate concerns (UI chrome vs. data encoding).

**Choropleth / data-encoding color scale (separate from UI accent):** `Viridis` (Plotly's `color_continuous_scale="Viridis"`, per RESEARCH.md Pattern 3) — perceptually uniform and colorblind-safe, the standard scientific-visualization default. Used consistently across all 4 indicator layers (D-01) and both panels of the side-by-side comparison (D-02), so a viewer can compare color intensity meaning across tabs without relearning a new scale. `range_color` **must** be fixed to the indicator's global 2000–2022 min/max (RESEARCH.md Pitfall 4) — never left to auto-scale per animation frame.

**SHAP tab exception:** `shap.summary_plot` (matplotlib backend via `st.pyplot`) uses SHAP's own built-in diverging red/blue palette. Do not override it — it is the field-standard SHAP visualization already accepted by the academic community, and reimplementing it would be unjustified rework for this phase.

**`.streamlit/config.toml` values to set:**
```toml
[theme]
primaryColor = "#1B6CA8"
backgroundColor = "#FFFFFF"
secondaryBackgroundColor = "#EFF3F7"
textColor = "#1A1A1A"
font = "sans serif"
```

## Copywriting Contract

All user-facing copy is in Spanish (matches the thesis language and tribunal audience).

| Element | Copy |
|---------|------|
| App title (`st.title`) | "Impacto Económico del Estrés Hídrico" |
| App subtitle (`st.caption`, under title) | "TFB — Panel de resultados (2000–2022)" |
| Tab labels (`st.tabs`, locked verbatim by CONTEXT.md D-06) | "Mapa e indicadores" · "Modelo 1" · "Simulación" · "Interpretabilidad (SHAP)" |
| Indicator selector labels (comparison, D-02; pre-populated from RESEARCH.md Pattern 2) | "Indicador (izquierda)" / "Indicador (derecha)" |
| Primary CTA | Not applicable — this is a passive/reactive dashboard with no submit-style action (Streamlit re-renders automatically on any widget change; there is no form to "submit"). The primary interactive affordance is indicator/model selection via `st.selectbox`, whose labels are specified above. |
| Empty state (per-country, choropleth no-data) | Countries with insufficient coverage render in Plotly's native gray "no data" fill. Add a `st.caption` under each map: "Los países en gris no disponen de datos suficientes para este indicador o fueron excluidos por cobertura mínima (ver Fase 2)." |
| Error state (missing/corrupt artifact — e.g. `panel.db` or a `.pkl` not found) | `st.error("No se pudieron cargar los datos del panel. Verifica que 'data/panel.db' existe y contiene la tabla 'panel_clean'. Ejecuta primero el pipeline de ingesta (Fase 1) y de modelado (Fase 3/4) antes de abrir el dashboard.")` — states the problem and the exact next step, per contract. |
| Destructive confirmation | Not applicable — no destructive actions exist in this phase (read-only dashboard, no delete/overwrite/reset controls) |

**Native, unstyled copy (excluded from this contract by design):** Plotly's `animation_frame` play/pause button and slider labels are rendered natively in English ("Play"/"Pause") per D-05's explicit choice to use Plotly's built-in mechanism as-is, without custom relabeling. Do not attempt to localize these via `updatemenus` overrides — that would contradict D-05 and add fragile custom Plotly config for no requirement-driven benefit.

## Plan B Screenshot Contract (DASH-05)

Not a template-standard dimension, but directly load-bearing for this phase's D-08 (screenshot-based backup) — captured here so the executor has one place to check visual consistency requirements for the pre-rendered backup:

- Capture each of the 4 tabs **after** all data/charts have fully rendered (no Streamlit spinner, no "Running..." indicator visible) — a screenshot mid-load looks unprofessional in front of a tribunal.
- Use the same browser window size for all 4 captures (recommend maximized/full-width, matching `st.set_page_config(layout="wide")`) so the backup deck looks like one consistent walkthrough, not four mismatched crops.
- For the "Mapa e indicadores" tab, capture with both choropleths showing the **same year** selected (not one mid-animation and the other reset) — reinforces D-02's "side-by-side, same year" framing.
- Save captures under `figuras/plan_b/` (mirrors the existing `figuras/` convention already used elsewhere in the repo for exported outputs).
