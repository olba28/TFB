**1. [FIXED — methodological] VIF computation lacked a constant/intercept column.**
`statsmodels.stats.outliers_influence.variance_inflation_factor` is conventionally
called on a design matrix that includes a constant column (via
`statsmodels.tools.add_constant`) — omitting it changes the resulting VIF values
and is a common, easy-to-miss pitfall in EDA notebooks. **Fix applied:** Task 2's
behavior/action now explicitly requires `add_constant` before VIF, documented
alongside the pairwise/listwise NaN-handling choice, with the constant column
itself excluded from the reported VIF table.

**2. [Consistency check, no fix needed] This plan's Task 1 read_first cites
01-05-SUMMARY.md's raw per-indicator coverage numbers (e.g. 2.3.1 = 50 countries,
173/900 non-null) as a sanity check for the notebook's own computed missingness
figures. This is valid ONLY because 02-01-PLAN.md's Review Notes fix #3 (see that
plan) changed `build_clean_panel` to never null real values — `panel_clean`'s
missingness pattern is therefore a faithful reflection of `raw_observations`'
natural missingness, and the 01-05-SUMMARY numbers remain a valid cross-check. Had
02-01's original data-nulling design shipped as originally drafted, this
sanity-check assumption would have been silently wrong (panel_clean would show
MORE missingness than the raw data, for reasons unrelated to actual non-reporting).
No change needed here now that the upstream plan is corrected — flagging only so
the dependency between the two plans' designs is visible.

**3. [Minor, not fixed — acceptable] `region`/typology groupby may produce a
`None`/`NaN` group** if any country has no region match (per 02-01's Fix #5
handling of shallow-nesting edge cases). `pandas.groupby` handles `None` values as
their own group without erroring, so this does not block notebook execution, but
the resulting group label may render as `NaN` in a table — acceptable for an EDA
notebook, not worth adding extra handling for what should be a rare/nonexistent
case in the real UN data (both maps come from the same tree).
