must_haves and Plan 02-02 reference them):

- `src/ingesta/typology.py`:
  - `SDG_REGION_ROOT_NAME = "World (total) by SDG regions"` — module constant, the
    exact `geoAreaName` used to select the correct root from the `GeoArea/Tree`
    response list (there are 7 roots; this one is the region source).
  - `DEV_STATUS_ROOT_CODES = {"is_ldc": 199, "is_lldc": 432, "is_sids": 722}` —
    module constant mapping each boolean flag name to its `geoAreaCode` root
    (verified live in 02-RESEARCH.md Finding 1).
  - `build_region_map(tree_data: list[dict]) -> dict[str, dict[str, str]]` — returns
    `{country_code: {"region": ..., "subregion": ...}}` (keyed by the raw M49 code
    at this stage — ISO3 conversion happens later in `build_country_reference`) by
    a RECURSIVE walk of the `SDG_REGION_ROOT_NAME` root (mirror
    `countries.collect_countries`'s recursive `walk(node, parent_name)` pattern —
    do NOT assume a fixed depth-3 region->subregion->country structure; the live
    `GeoArea/Tree` shape was only spot-checked to 2 levels during research and may
    contain a country directly under a top-level region with no subregion in
    between). Track the two nearest named ancestors seen so far as the walk
    descends; when a `type == "Country"` leaf is reached, record the immediate
    parent as `subregion` and the parent's parent as `region` — if there is no
    grandparent (country found directly under the top-level region), set
    `subregion = None` and `region = <the one ancestor name available>` rather than
    raising or dropping the country.
  - `build_development_status_flags(tree_data: list[dict]) -> dict[str, dict[str, bool]]`
    — returns `{country_code: {"is_ldc": bool, "is_lldc": bool, "is_sids": bool}}` by
    walking each root in `DEV_STATUS_ROOT_CODES` to its country leaves; a country not
    found under a given root gets `False` for that flag (default, not absence).
  - `build_country_reference(tree_data: list[dict], crosswalk: dict[str, str]) -> pd.DataFrame`
    — merges the two maps above (both keyed by the **M49 code**, since that is what
    `GeoArea/Tree` walks produce) into one DataFrame, THEN maps the M49 key to
    **ISO3** via `crosswalk` (built by `src.ingesta.countries.build_crosswalk()`) —
    the final DataFrame's `country_code` column is ISO3, matching
    `raw_observations.country_code`'s schema exactly (D-11/D-12 precedent: `db.py`'s
    `CREATE_RAW_OBSERVATIONS` documents `country_code TEXT -- ISO3`). Any M49 code
    with no crosswalk entry is EXCLUDED from the returned DataFrame and collected
    into a second return value, `excluded: list[dict]` (mirrors `countries.py`'s
    `filter_to_countries` exclusion-logging precedent — never silently dropped
    without a record). Returns `(pd.DataFrame, list[dict])`.
  - `capture_country_reference(session: requests.Session) -> tuple[pd.DataFrame, list[dict]]`
    — fetches `GeoArea/Tree` once (same URL constant pattern as `fetch_data.py`'s
    `GEOAREA_TREE_URL`), builds the crosswalk via
    `src.ingesta.countries.build_crosswalk()` (pure file read, no network call),
    and calls `build_country_reference(tree_data, crosswalk)`.
  - `persist_country_reference(df: pd.DataFrame, path: Path = Path("data/raw/country_reference.json")) -> Path`
    — writes the ISO3-keyed DataFrame as JSON records to `path` and writes the
    provenance sidecar via `src.ingesta.manifest.write_manifest` (reusing the
    existing date/url/params/row_count/checksum schema; `params={}`,
    `url=GEOAREA_TREE_URL`).
  - `persist_country_reference_to_db(df: pd.DataFrame, engine: Engine) -> None` —
    writes the same ISO3-keyed DataFrame to a `country_reference` SQL table via
    `df.to_sql("country_reference", engine, if_exists="replace", index=False)`
    (mirrors `db.rebuild_panel`'s "always fully regenerate" convention). This is
    the table Task 2's `rebuild_clean_panel` reads via `pd.read_sql` — Task 1 MUST
    produce this table, not just the JSON file, or Task 2/3 have nothing to join
    against.
  - `python -m src.ingesta.typology` CLI entry — runs `capture_country_reference`,
    then BOTH `persist_country_reference` (JSON + manifest) AND
    `persist_country_reference_to_db` (SQL table, via `src.db.get_engine()`)
    end-to-end, plus writes `excluded` (from `build_country_reference`) to
    `data/raw/country_reference_exclusion_log.json` (mirrors D-16's
    `exclusion_log.json` precedent — never silently drop an unmapped M49 code).

- `src/panel_build.py`:
  - `YEARS_REQUIRED = 17` — module constant (23 possible years × 0.70 = 16.1 → 17,
    per 02-RESEARCH.md Finding 4).
  - `TOTAL_YEARS = 23` — module constant (2000–2022 inclusive).
  - `compute_coverage(raw_observations: pd.DataFrame, country_reference: pd.DataFrame, indicator_codes: list[str]) -> pd.DataFrame`
    — returns one row for **every** `(country_code, indicator_code)` pair in the
    full cross-product of `country_reference`'s countries × `indicator_codes`
    (NOT only pairs already present in `raw_observations`) with columns
    `country_code, indicator_code, years_available, years_required, coverage_pct,
    excluded` (`excluded = years_available < YEARS_REQUIRED`). A country with ZERO
    rows at all for a given indicator (e.g. most countries for `2.3.1`, per
    01-05-SUMMARY.md's 50-of-215-country coverage) must still appear as a row with
    `years_available = 0`, not be silently absent from the coverage accounting.
  - `build_exclusion_table(coverage: pd.DataFrame) -> pd.DataFrame` — filters
    `compute_coverage`'s output to `excluded == True` rows only, adds a `reason`
    column: `"no_data_reported"` when `years_available == 0`, otherwise
    `"coverage_below_70pct_threshold"` (both are the same underlying 70% rule; the
    finer-grained reason string is purely for documentation clarity per PANEL-02's
    "documentando las exclusiones... y por qué").
  - `build_clean_panel(raw_observations: pd.DataFrame, country_reference: pd.DataFrame) -> pd.DataFrame`
    — pivots `raw_observations` the same way `db.rebuild_panel` does
    (`country_code, year` index, `indicator_code` columns) and joins
    `country_reference` columns (`region, subregion, is_ldc, is_lldc, is_sids`).
    **Does NOT null or otherwise alter any indicator value based on the coverage
    threshold** — every real, reported observation is preserved as-is, including
    for countries/indicators that fail the 70% threshold. The coverage/exclusion
    decision is exposed ONLY via the separate `panel_exclusions` table (built from
    `compute_coverage`/`build_exclusion_table`); downstream consumers (Phase 3's
    modeling) decide whether to honor an exclusion by filtering against
    `panel_exclusions` at estimation time. Rationale (Review Notes below): silently
    nulling real, already-reported values inside `panel_clean` itself would destroy
    information a downstream analyst might legitimately want (e.g. a robustness
    check on the excluded subsample) and conflates "this doesn't meet an arbitrary
    coverage bar" with "this data doesn't exist" — the two are different claims,
    and PANEL-02 only requires filtering to be DOCUMENTED, not that the clean panel
    itself be pre-filtered. A country never has its ROW dropped from `panel_clean`
    regardless of any indicator's coverage status, per 02-RESEARCH.md Finding 4.
  - `rebuild_clean_panel(engine: Engine) -> None` — reads `raw_observations` +
    `country_reference` tables from `engine`, calls `compute_coverage` (full
    cross-product), `build_exclusion_table`, and `build_clean_panel` (unfiltered,
    per the corrected behavior above), writes `panel_clean` (`if_exists='replace'`,
    mirrors `db.rebuild_panel`) and `panel_exclusions` (`if_exists='replace'`)
    tables back via the same `engine`.
  - `python -m src.panel_build` CLI entry — calls `db.get_engine()` +
    `rebuild_clean_panel(engine)` end-to-end against the real `data/panel.db`.

### Blocking issues found and fixed

**1. [FIXED — critical] M49 code vs. ISO3 code key mismatch.** The original draft
had `build_region_map`/`build_development_status_flags`/`build_country_reference`
keying their output by `_normalize_code(geoAreaCode)` — the raw M49 numeric code —
and joining that directly against `raw_observations.country_code`, which is ISO3
(per `db.py`'s own schema comment: `country_code TEXT NOT NULL, -- ISO3`). This is
**the exact same class of bug** Phase 1 hit and fixed live during Plan 01-05
(`f55be2d`, "geoAreaCode format mismatch across GeoArea/Tree, Indicator/Data, and
the M49 CSV crosswalk" — see `01-05-SUMMARY.md`'s deviation log): without a
crosswalk step, the join would silently produce zero matches across the board,
exactly like the original Phase 1 incident description ("zeroing out
`raw_observations` across all 5 indicators on the first live run"). **Fix applied:**
`build_country_reference` now takes an explicit `crosswalk` parameter (built via
`countries.build_crosswalk()`, the same function Phase 1 already validated) and
converts every M49-keyed row to ISO3 before returning, logging any code with no
crosswalk match to an `excluded` list rather than silently dropping or mis-joining
it — mirroring `countries.filter_to_countries`'s existing pattern exactly.

**2. [FIXED — blocking] Task 1 never persisted `country_reference` as a SQL table,
but Task 2/3 assumed it existed.** The original Task 1 artifacts only specified
`persist_country_reference` (writes JSON + manifest). Task 2's `rebuild_clean_panel`
behavior spec required reading a `country_reference` **table** via `pd.read_sql`,
and Task 3's acceptance criteria checked for a `country_reference` table in
`data/panel.db` — neither of which Task 1 actually produced. As originally written,
Task 3 would have failed its own acceptance criteria (table would not exist). **Fix
applied:** added `persist_country_reference_to_db(df, engine)` to Task 1's
artifacts/behavior/action, and the CLI entry (`python -m src.ingesta.typology`) now
explicitly calls both persistence functions.

**3. [FIXED — data-integrity/methodological] `build_clean_panel` originally nulled
real, already-reported observations for any country/indicator failing the 70%
threshold.** The original design set an entire indicator column to `NaN` for a
country once that `(country, indicator)` pair failed coverage — destroying real
API-reported values, not just documenting the shortfall. This conflates two
different claims ("this doesn't meet an arbitrary coverage bar for a specific
downstream use" vs. "this data doesn't exist") and would make a robustness check on
the excluded subsample impossible later (Phase 3's MODEL1-05 explicitly requires
"al menos una comprobación de robustez ... especificación alternativa o
submuestra" — destroying the very subsample data needed for that check would be
counterproductive). PANEL-02's wording only requires the filtering to be
**documented**, not that the underlying data be destroyed. **Fix applied:**
`build_clean_panel` now preserves every real value unmodified; the
coverage/exclusion decision lives exclusively in the separate `panel_exclusions`
table, and downstream consumers (Phase 3) filter against that table at estimation
time rather than finding pre-nulled cells. This is presented as a considered
correction, not a silent judgment call — **if the user (or Phase 3's planner)
prefers the original "null the excluded cells in `panel_clean` itself" design for
some methodological reason (e.g. wanting a single "modeling-ready" table with no
further filtering step), that is a legitimate alternative and should be raised
explicitly before or during Phase 3 planning.**

**4. [FIXED — completeness gap] `compute_coverage` originally only considered
`(country, indicator)` pairs already present in `raw_observations`, silently
omitting country/indicator combinations with ZERO rows at all** (e.g., roughly
165 of 215 countries have no rows whatsoever for indicator `2.3.1`, per
01-05-SUMMARY.md's "50 countries, 173/900 non-null" figure — 900 possible cells
minus far fewer actual rows). These zero-row pairs would not appear in
`panel_exclusions` at all under the original design, which under-documents
exactly the exclusions PANEL-02 requires. **Fix applied:** `compute_coverage` now
iterates the full cross-product of every country in `country_reference` × the 5
fixed `INDICATOR_CODES`, so a country with zero reported years for an indicator
gets an explicit `years_available = 0` row with `reason = "no_data_reported"`.

**5. [FIXED — robustness] `build_region_map`'s original spec assumed a rigid,
fixed depth-3 walk (region → subregion → country) without having verified the
live `GeoArea/Tree` structure holds that shape for every branch** (the research
pass's live spot-check only printed the first 6 children at `max_depth=2` for 3 of
7 roots — not exhaustive). A country appearing directly under a top-level region
with no subregion in between would have silently gotten no region/subregion under
the original fixed-depth description. **Fix applied:** `build_region_map` now
specifies a recursive walk (mirroring `countries.collect_countries`'s own
recursive pattern) that tolerates shallower nesting, with a dedicated test case
for a country found directly under a region (no subregion).

### Minor issues found and fixed

**6. [FIXED] Task 3's 2.3.1-exclusion acceptance criterion used subjective,
non-scriptable language** ("prints a count consistent with... most of the ~215
countries") — violates the plan-authoring rule that acceptance criteria must never
use subjective language. Replaced with a concrete, hard-coded numeric threshold
(`>= 150 countries`, derived from the known 50-of-215-country 2.3.1 coverage) that
a script can evaluate to a plain `OK`/`TOO_FEW:<n>` output.
